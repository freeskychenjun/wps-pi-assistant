## 二、改了什么（按文件）

### `bridge.js`

- **安全门**（请求入口统一处，所有路由都过）：
  - `hostAllowed(host)`：只认 `127.0.0.1` / `localhost` / `[::1]`，否则 `403 forbidden: host`（挡 DNS rebinding）。
  - `originAllowed(origin)`：回环任意端口、`*.wps.cn` / `*.kingsoft.com` / `wps://`、`wps-plugin://`、`ksolaunch://`；`Origin: null` 与**无 Origin**（命令行、本机脚本）放行。
  - 有合法 Origin 时**回显该 Origin**并加 `Vary: Origin`（不再无条件 `*`）；`/events` 的 SSE 头也去掉了 `*`（原先会覆盖安全门的结果）。
  - `Allow-Headers` 收敛成 `Content-Type`。
- **静态目录穿越**：`/addin/*` 解析后必须落在 `ADDIN_DIR` 内（`startsWith(ADDIN_DIR + path.sep)` 或全等）。
- **异步化**：`execSync("pi --list-models")` → `execCmd()`（Promise 包 `exec`），`listModels()` 变 async 并加 `modelsPending` 去重（`/models` 并发点刷新只会真跑一次）；`killPi()` 的 `taskkill` 同样改 `execFile` 异步，并顺手 `setBusy(false)`。
- **并发锁**：`setBusy(on, why)`；`/prompt` 入口 `busy` 时回
  `409 {ok:false,error:"上一条消息还在处理中，等它结束（或点「停止」）再发。"}`；
  解锁点在 `agent_end`、`response.success===false`、子进程 `exit`、`/stop`；另有 10 分钟定时兜底，防「进程还活着但事件丢了」把面板永久锁死。
- **日志轮转**：`appendLog(file, line)` + `LOG_MAX_BYTES = 2 MB`，超限把现文件 rename 成 `.1` 再写；全仓 `fs.appendFileSync(log...)` 都改走它（`/log`、`/doclog`、`/docreq`、`/config`、`/context`、`/prompt`、`/prune`、启动行、`crashLog`）。

### `pi-assistant/js/taskpane.js`

- **`parseBlock` 多块**：带 `g` 的正则收集**同一 tag 的全部块**，逐块 `JSON.parse` 后合并（数组字段按顺序 `concat`，标量取第一块），`clean` 用全局 replace 剥掉全部块；任何一块解析失败 → 警告文本进气泡（`out.warn`），其余块照常执行。
- **`stripBlocks` 覆盖全部 11 类**：以前只剥 7 类，`wps-cells` / `wps-headerfooter` / `wps-page` / `wps-format` 的原始 JSON 会漏进聊天气泡（含 `done` 时的 Markdown 重排）。现在由 `BLOCK_SPECS` 统一剥。
- **`doc_eval` 黑名单**：单条正则 → `EV_WRITE_PATTERNS` 数组（`TrackRevisions`、`.Save(As)(`、`.Delete(`/`.Cut(`/`FileCopy`/`WScript`/`Shell(`、`.Paste`/`.Copy(`、`InsertBefore(`/`InsertAfter(`/`InsertParagraph*`、`TypeText(`/`.Add(`、`.Clear(`/`.Undo(`/`.Redo(`、`Range(...).Text =`、`Text =`、`["Content"] =` 一类下标写）。命中时错误信息带**命中的是哪一条**，方便模型自己换只读写法。
- **`findText` 惰性判定**：先 `indexOf` 命中，**再**调 `pr.Information(12)` 判表格。原顺序反了——0 命中的全篇检索也要为每段付一次 `Information` 往返。
- **`dev_apply` 合一**：删掉永远走不到的「edits 数组版」，合成一份：支持 `req.text`（按正式解析链跑）与 `req.edits`（直接 `applyEdits`），都带 `[dev_apply elapsed=…ms]`。
- **`applyEdits` 的 `insertAfter` 局部失效**：`pTexts = null` → 读回新段真实文字后 `splice(hitAt+1, 0, text)`（`Paragraphs.Count` 不等于 `len+1` 时——表格内/文末等——才退回全篇重读）。连续插入 N 段不再 N 次全读。
- **`undoLastTurn` 有界拒绝**：`while (Count > from-1) Reject()` → 只拒 `[from, to]`，**从 `to` 倒着拒**（拒绝低序号会让高序号前移），900 上限防死循环；`Count < from`（已被手工处理）时直接跳过文本级还原。提示语补一句「只回退本轮 AI 修订，你自己在 WPS 里做的修订不受影响」。
- **`BLOCK_SPECS` 数据驱动**：解析顺序 / 标签 / 中文名 / 字段名 / 执行函数 / 计数单位收进一张表；`parseAllBlocks()` 一次跑完解析链，`finishTurn()` 循环执行，`done` 事件不再手写 11 次 parse + 11 项 `blocks` + 11 项求和（`addBlockDisclosure` 本来就用 `parts[].name`，自然跟着表走）。新增一类指令现在只加一行。
- **工具刷屏**：连续 `tool` 事件合并成同一行（`toolNames` 缓存 + 复用 `toolMsgEl`，超过 6 个显示「…（共 N 次）」），`done` / `error` 时结算归零。
- **`sendMsg` 透出原因**：`j.ok === false` 时显示 `j.error`（例如 409 的并发提示），不再一律「pi 未启动或会话切换失败」。

### 文档与打包

- `README.md`：Node 要求统一为 **22+**；新增「安全边界（v0.2.16 收紧）」小节（四道门 + 日志轮转 + 撤销范围）；`dom.htmlVer` 的排障口径改成「显示发布版本号」；里程碑补 `v0.2.10`–`v0.2.16`（**v0.2.16 是本次改动对应、尚未打标签的待发版**；README 里已注明，打标签后才算发布）。
- `pi-assistant/ui/taskpane.html`：`<meta name="ver" content="dev">`（开发态不再伪装成某个内部代号 `p31`）。
- `pack-release.ps1`：版本号仍以 **git 标签**为唯一来源，打包时注入到 **staged** 的 `taskpane.html`，注入后校验「`content="<version>"` 确实在包里」，不在就 `Fail`。
- `pi-assistant/package.json`：`version` 由 `0.1.0` 对齐到 `0.2.15`，`description` 去掉过期的「（P0 验证版）」（该文件只服务 `wpsjs` 开发工具，不参与打包，故不作为版本来源）。

## 三、不采纳的理由

1. **#14 拆 taskpane.js（3066 行）**：报告给的方案是「多个 `<script>` 顺序引入」，看似零依赖，但 6 个文件共享 `window` 上的一堆隐式全局（`BRIDGE`、`undoStack`、`docKey` 缓存、`mdToHtml`…），拆分等于**先把隐式全局显式化**再搬代码——真实工作量在「理清全局状态」，不在「挪文件」。收益是可读性，代价是：发布包多 5 个文件、加载顺序成为新故障点（WPS webview 里脚本顺序错就是白屏，且没有 source map 好查）、`test-apply-perf.js` 这类按源码切片做单测的脚本全部要改。当前没有任何功能被 3066 行挡住，故**不做**。真要做，前置条件是加打包器（`vite` 已在 `pi-assistant/devDependencies` 里，`wpsjs debug` 也在用）+ 一次性把状态收进一个 `state` 对象，属于独立任务。
2. **#11 的 `Content.Text` 统一 helper**：`doc.Content.Text` 一次读完再本地按 `\r` 切，确实能把 `readInfo`/`readParagraphs` 的 COM 次数从 O(段数) 降到 1。但这两处**要的是段号映射**（`doc_read what=paragraphs start=100 end=140` 的 `index` 就是 `Paragraphs.Item` 的序号），而 `Content.Text` 切分出来的段号在「表格内段落、文本框、分节符、脚注」这几类文档上**与 `Paragraphs` 集合不一致**——报告自己也写了「切分段数 ≠ Count 时回退」，可这个回退恰恰会在最需要它的文档上触发，等于多写一套代码却只在小文档上省几十毫秒（实测 `readParagraphs` 读 4000 段约 8 秒，远在 25 秒超时内）。`readOutline` 还要逐段 `Style.NameLocal`，本来就没法单读。所以只采纳其中**确定无副作用**的那半条（`findText` 的惰性 `Information`），不做统一 helper。`readAll` 已经有 `Content.Text` 单读路径，需要「全文一次读」时用它就够了。
3. **#4 API Key 明文**：威胁模型是「本机其他程序能读 `%APPDATA%` 下的文件」。要给这层加密，密钥只能放在同一台机器（DPAPI 或固定口令），拿到文件的攻击者同样能解——收益接近 0，却多一条「换机器/重装后配置读不出来」的坑。现状靠 `.gitignore` + 发布包白名单（`pack-release.ps1` 显式 `Fail` 禁止 `bridge-config.json` 入包）已经挡住了最现实的泄露路径（误提交、误分发）。
4. **#17 的根 `package.json` + CI**：这是单人本机插件，没有远程仓库托管、没有合并请求流程；`test-apply-perf.js` 本来就是 `node test-apply-perf.js` 一行跑完，加一层 `npm test` 只是多一个要维护的文件。版本单源这条**有价值的**部分已采纳。
5. **#18 多文档并发**：需要「每 docKey 一个 pi 子进程 + 活跃数上限 + 会话按文档绑定」，还要处理内存与鉴权（多个进程各自持 key）。这是功能，不是优化，得按需求排期。
6. **#19 上下文 token 膨胀**：正解是 pi rpc 支持 ephemeral/system 消息（不进历史）；当前协议没有，只能在 system prompt 里约定，属于「写了也不保证生效」的软化措施，不建议现在动。
